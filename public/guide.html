Запуск на сервере

Понадобятся отдельная машина Linux или Windows, Node.js 24+, Docker с Compose и собственный домен. Текущая локальная версия доступна только на вашем компьютере.

1. Домен и HTTPS

  1. Перенесите папку приложения на сервер.
  2. В DNS домена создайте A-запись с IP сервера. Если есть AAAA-запись, IPv6 тоже должен вести на этот сервер.
  3. Разрешите входящие TCP-порты 80 и 443. Они должны быть свободны для Caddy.
  4. Из папки приложения выполните команду, заменив домен своим:
node deploy/setup.mjs monitor.example.com --start

Скрипт создаст .env.production со случайными ключами и запустит Docker Compose. Ключ входа находится в поле ACCESS_KEY. Caddy получит и будет продлевать TLS-сертификат. Папка данных и сертификаты сохраняются в томах Docker.

Если настройки уже существуют, скрипт не перезаписывает их. Повторный запуск и обновление:

docker compose --env-file .env.production -f compose.production.yaml up -d --build
docker compose --env-file .env.production -f compose.production.yaml logs -f

Панель откроется по адресу https://ваш-домен. Приложение не публикует порт 4310 наружу. Для выпуска сертификата серверу нужен доступ к интернету. Команды выполняйте из папки приложения.

2. Telegram

  1. Создайте бота в Telegram через @BotFather и получите токен.
  2. Напишите боту /start либо добавьте его в нужную группу и разрешите отправку сообщений.
  3. Укажите токен и Chat ID в настройках Pulsewatch, включите отправку и сохраните.
  4. Нажмите «Отправить тест». Результат смотрите в журнале доставки.

Chat ID можно получить через метод getUpdates вашего бота после входящего сообщения: значение message.chat.id. Не передавайте токен сторонним сайтам. Для бота с действующим webhook получите Chat ID из входящего webhook-события. Инструкция и параметры методов: Telegram Bot API.

При смене получателя неотправленные сообщения прежнего канала отменяются. Тест отправляется только по кнопке. Напоминания прекращаются после принятия инцидента или восстановления.

3. Независимый наблюдатель

Установите копию приложения на другую машину. Наблюдатель проверяет Pulsewatch каждые 30 секунд, подтверждает отказ после 3 ошибок и восстановление после 2 успехов. Обе машины должны иметь точное системное время.

  1. В панели откройте «Внешний наблюдатель» и получите адрес и отдельный ключ подключения.
  2. На второй машине скопируйте .env.watchdog.example в .env.watchdog.
  3. Заполните адрес, ключ и канал Telegram или webhook. Эти настройки хранятся на второй машине, поэтому отказ Pulsewatch не мешает отправке.
docker compose -f compose.watchdog.yaml up -d --build
docker compose -f compose.watchdog.yaml logs -f

Без Docker: npm run watchdog. Для автозапуска используйте systemd или Планировщик заданий. Сам наблюдатель должен оставаться запущенным. Его потеря связи видна в настройках Pulsewatch, пока основная панель доступна.

4. Резервные копии и восстановление

По умолчанию копия создаётся каждые 24 часа; хранятся 7 успешных копий. Кнопка в настройках запускает копирование вручную. SQLite копируется согласованно во время работы и проверяется на целостность.

При обычном запуске: data/backups. В Docker — /app/data/backups внутри тома приложения. Параметры: BACKUP_HOURS, BACKUP_KEEP, BACKUP_DIR.

docker compose --env-file .env.production -f compose.production.yaml cp pulsewatch:/app/data/backups ./saved-backups

Копия содержит адреса, историю и секретные ключи. Храните её приватно и переносите на другой диск или сервер: копия на том же диске не защищает от его отказа.

Остановите приложение и восстановите копию в новый пустой каталог:

node deploy/restore.mjs ./saved-backups/backup-ИМЯ ./restored-data

Затем задайте DATA_DIR равным этому каталогу и запустите приложение. Файл runtime-settings.json в копии содержит параметры запуска для восстановления. Скрипт не заменяет существующие данные. При переносе из локальной версии сначала создайте и восстановите копию в том production-контейнера перед первым запуском.

5. Точные тревоги и графики

В карточке сервера доступны графики за 24 часа и 7 дней. Среднее и пик показываются отдельно; разрывы означают отсутствие данных. Открытая карточка обновляется каждые 5 секунд.

В параметрах проверки задайте количество ошибок, успехов до восстановления, длительность перегрузки и период напоминаний. Расписание техработ бывает разовым или еженедельным с часовым поясом; поддерживается переход через полночь. На графиках техработы остаются, а новые тревоги и напоминания подавляются.
